# GTD (Getting Things Done)

Em uma frase: tire tudo da cabeça (**capturar**), decida o que cada coisa é e onde vai (**esclarecer e organizar**), e olhe para o sistema regularmente para confiar nele (**revisar**).

## As etapas e onde vivem nesta base
- **Capturar**: tudo entra em `00 Inbox/`, sem filtro, uma nota por ideia. Manual: você cria a nota.
- **Esclarecer**: para cada item, *é acionável?* Não → descartar, referência (`03 Resources/`) ou [[Algum dia]]. Sim → menos de 2 minutos, faça; mais de um passo, é projeto; senão, próxima ação de um projeto ou área. Skill `process-inbox`.
- **Organizar**: o destino segue [[PARA]].
- **Revisar**: revisão semanal (skill `weekly-review`) e diário (skill `daily-log`). "Revisão rima com versão": cada revisão termina em commit.
- **Fazer**: quando travar, `next-action` devolve uma ação só.

## A regra que sustenta tudo
Todo projeto tem **um próximo passo** escrito, que começa com verbo e cabe numa sentada. Projeto sem próximo passo é o que faz o sistema perder a confiança.
